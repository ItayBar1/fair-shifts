## מעבר האבטחה בשרת — 08.10.2026

המשתמש אישר לבצע את המעבר, בדיקות הקבלה וחידוש הטיימר לאחריהן. בשרת staging פעילה `fadf468` תחת `fair-shifts-production-alpine`: אתר ועובד מאותה גרסה, PostgreSQL 18.6 בנפח חדש ו־Tunnel חדש. בריאות השירותים ו־HTTP 200 אומתו ב־19:05. ה־checkout בשרת וקובצי התצורה הרגילים עודכנו; הגדרת systemd לפרויקט Alpine הותקנה אחרי sudo של הטכני ואומתה. **הטיימר עדיין מושהה באמצעות paused.** המקור, התמונות, התצורה והמסד הישנים נשמרו לחזרה.

לפני המעבר בוצעו שחזור מבודד ב־Docker, מעבר תצורה והרשאות, מפתחות Ed25519 עם עותק חיצוני מאומת, והסבות v2 (אפס סודות/רשומות ישנות להסבה). גיבויים מוצפנים ותצורה נשמרו מחוץ לשרת. תרגיל Alpine וגיבוי סופי עם כתיבות עצורות עברו: 17 מיגרציות, קשרי נתונים ובדיקות מחיקה; נותרה אזהרת גרסאות קיימת אחת. מפתח הפענוח המקורי נשאר במחשב הטכני.

פקודת restore promote הנפרדת פתחה חיבור לבדיקת הרשאות וחסמה את עצמה. ההחלפה הושלמה בנעילת הפריסה לאחר בדיקת דוח שעבר והיעדר חיבורים, עם משתמש התפעול ללא superuser. בענף `codex/security-live-acceptance` תיקון הסוגר את ה־pool לפני החלפה ורגרסיה שמוודאת הצלחה וחסימת חיבור חיצוני; שבע בדיקות הרשאות עברו ב־Docker. שער מלא וסקירה נדרשים לפני מיזוג.

חסר לסגירה: גיבוי ותרגיל נוסף מהעובד החדש, בדיקת כניסה בקוד, שינוי מייל, משלוח, ייבוא ו־Calendar (עדיין כבוי), הדגמת כשל וחזרה, וחידוש ואימות מחזור טיימר. CSP עם nonce ובריאות ציבורית בסיסית אומתו. HSTS במקור תואם; התשובה הציבורית מוסיפה includeSubDomains/preload ונדרשת בדיקת Cloudflare. אין באתר סודות Brevo/Drive/חתימה. ראיות וגבולות: [תיעוד המעבר](../../docs/security-live-transition-evidence.md). אין לסגור כרטיסים או למחוק דוח לפני כל ראיות הקבלה.

כניסת Google עם חשבון הבדיקה שהמשתמש סיפק הצליחה למסך הטכני ב־19:16; גרסת אתר/עובד fadf468 ובריאות אומתו במסך. אין בכך הוכחה לכניסה של חייל או לאישור Calendar. הגיבוי החדש ממתין לחכירה שנשמרה בגיבוי ששוחזר; התאוששותו נבדקת.

## כללי המשך

עובדים בענפי `codex/`, מעדכנים מענף main במיזוג, מגבים commit/push ופותחים PR לסקירת המפתח השני. כל commit עובר מלוא Docker דרך Husky, ללא עקיפה או force push; אינטגרציה ו־E2E אינן רצות יחד באותו מסד. מתקינים hooks בכל worktree חדש. בסשן הזה התקנה ללא TTY נעצרה; התקנת Husky ישירות בשירות tools עם `CI=true` מאפשרת התקנה לא אינטראקטיבית. העברת `-e CI=true` ל־install-hooks.sh אינה מספיקה, כי git-mounts.sh מחליף את הארגומנטים.

סכמה חדשה רק אחרי main עדכני; יש לשמר SQL מותאם וטריגרים במיגרציות. תיקון עבר והכרעת ניקוד על חשבון שנמחק נשארים חסומים לפי הכרעה 196. מחיקה שומרת שם/מספר והיסטוריה לפי האפיון; שינוי מדיניות דורש הכרעה. [נוהל הצוות](../../README.md#נוהל-עבודה-בצוות).
