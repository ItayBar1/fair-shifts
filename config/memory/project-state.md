## המלצות מביקורת 17.10.2026

הביקורת המלאה ותיקוניה ב[מסמך האבטחה](../../docs/security.md#ביקורת-17102026). אלה ההצעות שלא מומשו. אין לגביהן החלטה, ואינן חוסמות:

1. **גודל מצב הלקוח.** כל ריענון (30 שניות לכל לשונית פתוחה) קורא את כל `records`, `ledger` והשיבוצים ושולח לחייל את כל ההיסטוריה שפורסמה. אין מדיניות שמירה להודעות. כדאי לסנן ב־SQL לפי תפקיד וחשבון, להוסיף ETag לפי גרסת היחידה, ולהגביל היסטוריה (שמירת הודעות היא החלטת מוצר).
2. **תמונה עקבית ב־`readState`.** הקריאה רצה ב־READ COMMITTED. מעבר ל־`repeatable read` דורש להסיר את `FOR UPDATE` מ־`assertActorCurrent` בקריאה (אחרת שגיאות 40001) או לנסות שוב כמו `readMyAssignments`.
3. **נגישות אחרי הרידיזיין.** לא נעשתה סריקה חוזרת. מביקורת 05.10: תפריט הנייד אינו סוגר ב־Escape ואינו מעביר מיקוד, ניגודיות בכיתובים קטנים במעטפת, וכותרת מסמך קבועה בכל המסכים. גם קורא מסך לא נבדק.
4. **פיצול רכיבים גדולים** כשנוגעים בהם: `management.tsx` (1,600 שורות), `views.tsx`, `fairness.tsx`, ובשרת `swaps.ts` ו־`transfers.ts`, שחולקים לוגיקה דומה.

## הערות תפעול

- **גישת SSH לסוכן:** מפתח `fair-shifts-claude` ב־`authorized_keys` של המשתמש בשרת, דרך Tailscale. אפשר להסיר כשאין בו צורך.
- **Fortinet ברשת של המשתמש** מיירט את `fairshifts.app` כדומיין חדש. ב־16.10 נשלחה ל־FortiGuard בקשת סיווג מחדש. מרשת אחרת האתר תקין.
- **מפתחות:** עותקי מפתח age ומפתח החתימה של יומן המחיקות שמורים אצל המשתמש כקבצים מקומיים. הומלץ עותק נוסף שאינו תלוי במחשב.
- **דומיין:** `fairshifts.app` נרכש ב־14.10.2026 לשנה ב־Cloudflare Registrar; לוודא חידוש אוטומטי.
