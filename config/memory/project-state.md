# מצב הפרויקט

עדכון: 28.09.2026 · שלב: מימוש ראשוני, עדיין לא גרסה מלאה.

## מה קיים

- [תוכנית מאושרת ב־20 שלבים](../../plans/fair-shifts-implementation.md), לכל 64 הסיפורים ו־52 תרחישי הקבלה. המשתמש הורה לממש את כולה.
- Next.js 16 / React 19 / TypeScript strict, Node 24, PostgreSQL 18, Drizzle, Better Auth, pg-boss; תלויות מדויקות ו־pnpm-lock.yaml.
- Dockerfile, Compose לפיתוח ולבדיקות, תמונת Playwright, מיגרציה ראשונה ל־20 טבלאות. כל הרצה ובדיקה בתוך Docker לפי הוראה מפורשת.
- כללי זמן ישראל, כשירות, תמחור מדויק וביצוע חלקי, רצועת הגרלה וניקוד; 16 בדיקות כללים.
- כניסה למוזמנים בלבד בקוד, נעילה אחרי 5 טעויות, גרסת אבטחה, שחרור וקודי שחזור חד־פעמיים. Google מוגדר בקוד אך טרם נבדק מול ספק אמיתי.
- קליטה ידנית, שיבוץ בטיוטה, פרסום, הודעת אתר ותור מייל, זקיפה פעם אחת, טבלת צדק, API עם גרסה ומניעת כפילות. בדיקות PostgreSQL כוללות תחרות על קוד/מקום/זקיפה, פרטיות ומכסה.
- ממשק עברי RTL למסלול הראשוני; חלק מהמסכים מציגים במפורש שהם בבנייה. אין להסיק שלמות ממספר המסכים.
- תור מייל מוצפן ומתאם Brevo; משלוח אמיתי כבוי ב־Compose. אין חשבונות ספקים או נתוני אמת.
- אימות שינוי מייל, תאריכי שירות והיסטוריית אוכלוסייה; תיקון עריכת אוכלוסייה בלי לשכתב את העבר.
- סבבי אילוצים עם כמה פריטים, החלטות נפרדות, גרסה מאושרת לצד ממתינה, היסטוריית גרסאות, פתיחה מחדש ותצוגת שיבוצים מושפעים עם בדיקת גרסה בזמן אישור.
- קטלוג דרגות ומסלולים, כללי פז״ם עם מקור וגרסה, מועד אישי, תזכורות עובד ואישור מפורש. אין קידום אוטומטי או כללי יחידה מובנים. תנאי דרגה בסוג ובתפקיד נשמרים במופע.
- תיקון יתרה ונרמול קבוצתי עם תצוגה מקדימה, בדיקת גרסאות וזקיפות שהגיע מועדן לפני הנרמול.
- שיבוץ ידני עם תצוגת התאמה וניקוד, אישור נפרד לכל חריג וסיבה. גרסת כללים נפרדת משינוי איוש; האישורים נבדקים שוב בפרסום ובשינוי נתוני חייל.
- הגרלה עם תמונת מועמדים, רצועת ניקוד והסבר לאחראי. הצעה ממתינה נשמרת ללא שיבוץ, נבדקת מחדש בהחלטה ונפסלת אם הנתונים השתנו. דחייה מוציאה מועמד מהמופע ומחשבת מחדש; אישור כללי לסקירת אילוצים אינו מחליף אישור להתנגשות.
- תכנון תקופה עם בחירת מופעים, שמירת מקום אחד בכל עסקה, עצירה לאישור והמשך ריצה. מעט מועמדים קודם, ואז מועד ומזהה; בתוך מופע התפקיד הנדיר קודם. סיכום חוסרים והודעת אתר לאחראים; ריצה נוספת ממלאת פנויים בלבד.
- הצעות שינוי לתורנות מפורסמת: עריכת מועדים, פרטים ושיבוצים; הצעה שאינה תופסת זמינות או ניקוד; השוואת מושפעים, מחיר ותנאים, ואישורים חדשים. ״עדכן ופרסם״ מחליף אטומית את הגרסה והשיבוצים השמורים, שומר גרסה היסטורית ומודיע למושפעים. דוח השפעת קטלוג והחלה מפורשת של מחירון והרכב דרך הצעה.

## מה אומת בפועל

Docker Desktop הופעל מחדש ב־28.09 כשהדמון לא היה זמין. 16 בדיקות כללים ו־37 בדיקות אינטגרציה, typecheck, lint ו־build עברו בתוך Docker. כוללת אישורי הגרלה מתחרים, רעננות הצעה, דחייה וחישוב מינימום חדש, תכנון וחידושו, סדר לפי נדירות, אישור פרטני לאילוץ ממתין, ועדכון מפורסם אטומי עם ביטול הודעות מייל ישנות שבתור והחלת קטלוג מפורשת.

E2E מול production בתוך Docker עבר במסלול קליטה, קוד, קטלוג, טיוטה, שיבוץ, פרסום, חייל ונייד, והגשת אילוץ עם אישור התנגשות. עברו גם הגדרת דרגות ופז״ם, אישור דרגה, תנאי דרגה בקטלוג ושיבוץ חריג עם תוספת אישית ופרסום. המסלול הורחב ועבר בתכנון תקופה, אישור לפני שחרור והמשך עד לסיום; וכן בהצעת שינוי, בדיקת הפרטיות עד לפרסום, אישור חדש ועדכן־ופרסם. נבדקו צילומי מחשב, נייד, דרגות והשוואת השינוי. האתר והעובד נבנו והופעלו מחדש ב־Docker; HTTP 200 ופעימת עובד אומתו. Google, Brevo ו־Drive אמיתיים לא חוברו או נבדקו.

## מה הבא

1. להשלים עריכה וביטול של טיוטות, החלת קטלוג על טיוטות, והרחבת בדיקות הגבול לתכנון ולשינויים שפורסמו. דוח הקטלוג זמין ביוזמת האחראי; תזכורות עתידיות מלאות וביטולן שייכים להמשך שלב 18. אין סימון שכל שלבים 10–12 הושלמו.
2. להשלים עריכת פטורים וכשירויות, פרטי הרכב ותמחור, ובדיקות גבולות לפי שערי השלבים.
3. להמשיך יתר שלבים 4–20: ייבוא ושחזור, תיקוני עבר, העברות/החלפות/ביצוע חלקי בממשק, תזכורות מלאות, מחיקה מלאה וגיבוי/שחזור. כל השלבים נותרים יעד הגרסה; אין סימון שכל שלב מוקדם הושלם במלואו.
4. להשלים מפת קבלה לבדיקות, אימות ספקים ותנאי הפעלה. CI מוגדר אך טרם רץ מרחוק.

## כללים ותלויות
