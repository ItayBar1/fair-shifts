## פערים מאומתים בביקורת

1. תיקון מבצע היסטורי משאיר התאמה ומנוחה לפי `assignment.soldierId`, במקום `performance.performerId`: החייל המקורי נשאר חסום והמבצע בפועל מותר. **6 שחזורי Docker נכשלו**. [ממצא וקוד שחזור](../../docs/audits/2026-10-05/implementation.md).
2. קבלת העברה אחרי סוף הביצוע כשהעובד מתעכב מחזירה **500** ומשאירה `awaiting_consent`. שחזור PostgreSQL נכשל בצפי 409/expired. אין טענה שהמקרה שוחזר בהחלפה הדדית.
3. חסר מסלול לתיעוד ביצוע אמיתי של טיוטה שפג מועדה; קיימת חלופת הביטול בלבד. אומת בשערי השירות, ללא שחזור מסד נוסף.
4. נימוקי דחייה בהעברות/החלפות נשלחים במייל בניגוד ל־PRD631. ניקוי תור המייל לפי הנמען הנמחק עלול להשאיר נימוק אצל משתתף אחר. גם טקסטים חופשיים מסוימים נשמרים בהיסטוריה. [דוח הפרטיות](../../docs/audits/2026-10-05/privacy.md).
5. חסרים יידוע מלא, ערוץ עיון/תיקון מתועד, מדיניות שמירה וספקים, ובירור בעל שליטה/הרשאה וסיווג אבטחה. אין לקבוע אוטומטית חובת GDPR, רישום, DPO או באנר opt-in. טיפול באסימוני Google תוקן בענף #92: אסימון יומן מוצפן בלבד, ללא אסימוני ספק בשורת Better Auth, וניקוי אסימונים ישנים במיגרציה.
6. סריקת 33 מסכים מצאה ניגודיות נמוכה; דגלי שמות נגישים בלוח דורשים בדיקה ידנית. תפריט הנייד אינו מעביר focus או נסגר ב־Escape. קורא מסך ותחולת החובה החוקית טרם נבדקו. [דוח נגישות](../../docs/audits/2026-10-05/accessibility.md).
7. מפת הקבלה מצהירה על 65/65 סיפורים ו־63/64 תרחישים (59 Calendar פתוח), אך אינה מוכיחה כיסוי סמנטי. בדיקת תפקיד אסור בפקודות חייל מאפשרת `status >= 400`, כולל 500, למרות חוזה 403 לפני קלט. יש לעדכן ראיות וכיסוי סביב הממצאים.

ממצאי קשיחות נוספים: curl ללא מגבלת זמן בפריסה, ורשימות Drive שאינן ממשיכות עמודים. מגבלה ידועה ב־#97: עדכון דחוף עשוי להישלח מיד, כשהפרסום המקורי נשאר במאוחד. נדרשת הכרעה על המקרה; זו אינה הוכחה לכפילות של אותו אירוע. [פרטים ותיעדוף](../../docs/audits/2026-10-05/README.md).

## בדיקות ומגבלות

בביקורת הורץ שירות `tests` המלא ב־Docker: migrations, טיפוסים, lint, כללים, בדיקות פריסה, **477 PostgreSQL** ובניית production עברו. שלוש בדיקות סריקה זמניות השלימו 33 מסכים ומלאי עוגיות בקוד; שבע בדיקות שחזור נכשלו ואימתו את שני הבאגים. תוצאות שער Husky המלא נרשמות ב[יומן הסשנים](session-log.md). כל המקורות לשחזורים נשמרו כטקסט בדוח, לצורך העברה לבדיקות בעת תיקון; אין עקיפת hook.

לא נבדקו כעת: שרת חי, גרסה פרוסה, סודות, מחיקה/שחזור אמיתי מ־Drive, ספקים מחדש, OAuth/עוגיות ב־HTTPS, קורא מסך, production ופיילוט. לא ניתן אישור משפטי או ארגוני. היסטוריית המימוש והבדיקות הקודמות נשמרת ביומן וב־Git; המצב הזה מחליף סיכומים ישנים וסותרים.

הערות להמשך: סכמה חדשה מוסיפים אחרי main העדכני; `drizzle/0001_fine_maverick.sql` כולל SQL מותאם וטריגרים שיש לשמר. תיקון עבר והכרעת ניקוד על חשבון שנמחק נשארים חסומים לפי הכרעה 196. שמירת שם/מספר והיסטוריה במחיקה היא דרישת מוצר; שינוי מדיניות שמירה חייב הכרעה ולא נעשה בשקט מתוך הביקורת.
