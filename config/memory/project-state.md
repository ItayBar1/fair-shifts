- שחזור עדכוני ייבוא לרשומות קיימות: תצוגה לפי גרסת כל שדה, החלטה נפרדת לכל התנגשות, וקביעת יתרה מפורשת לאחר פעולה מתערבת. פרטי קשר שנמחקו אינם מוחזרים ואינם מוצגים בתצוגת השחזור. היסטוריית דרגה ואוכלוסייה משחזרת רק מועדים שנגע בהם הייבוא, עם שמירת רשומות מאוחרות. השיבוצים נשמרים ונבדקים מחדש; החלטת שחזור נסגרת פעם אחת. קליטות חדשות נשארות ממתינות למדיניות שחזור, ולא מסומנות כשוחזרו.

## מה הבא

CI ב־GitHub עבר עבור main לאחר מיזוג PR #1, commit ‏`2ccf4f2` (ריצה 36418232940). יצירת הכרטיסים נבדקה בקריאה חוזרת של כל הגופים והתלויות; HTML 1.6, ‏88 קישורים מקומיים ומספור 64 סיפורים ו־56 מקרי קבלה אומתו ב־Docker. בסשן הכרטיסים לא שונה קוד יישום.

לתיאום בין שני המפתחים: לבחור בעלים ולבדוק תלויות בכרטיס לפני התחלה. משימות אפשריות ללא תלות עסקית: #12 תיקון עבר, #20 העדפות משלוח, #24 תצורת הפעלה, #30 מסנני חיילים, #31 לוח רב־יומי ו־#32 יומן פעולות; עדיין מתאמים קבצים משותפים. הגנת main לתיאום בכרטיס #29; Project טרם הוקם. אין להתחיל שני מימושים לאותו מסלול.

1. להרחיב בדיקות גבול לתכנון ולשינויים. עריכה וביטול של טיוטות והחלת קטלוג עליהן מומשו; E2E עבר בשינוי טיוטה ללא פרסום ובביטול מפורסם. ביטול אחרי תחילת ביצוע ותיעוד טיוטה שבוצעה שייכים להמשך מסלולי תיקון וביצוע. דוח הקטלוג זמין ביוזמת האחראי; תזכורות מלאות שייכות לשלב 18. אין סימון שכל שלבים 10–12 הושלמו.
2. להשלים שינויים מקומיים בהרכב ותמחור במופע, והרחבת בדיקות גבולות לפי שערי השלבים. עריכת פטורים, כשירויות ואי־פעילות מומשה; תצוגת השפעה לפני הוספת תקופה מוזגה (#5). מעבר אוכלוסייה, תאריכי קבע/קצונה וייבוא עוברים תצוגה מקדימה (כרטיס #46, לסקירה).
3. להשלים מדיניות שחזור קליטות חדשות בייבוא ב־[#8](https://github.com/ItayBar1/fair-shifts/issues/8), ובהמשך יתר שלבים 4–20 לפי הכרטיסים. הייבוא ושחזור עדכוני רשומות קיימות מומשו ומוזגו; השאלה על ביטול קליטה של רשומות חדשות בזמן שחזור עדיין אינה מוכרעת. אין לפעול כאילו הוכרעה. כל השלבים נותרים יעד הגרסה; אין סימון שכל שלב מוקדם הושלם במלואו.
4. להשלים מפת קבלה לבדיקות, אימות ספקים ותנאי הפעלה. CI עבר ב־GitHub עבור commit ‏`0e6a3b6` (ריצה 36389059041).
