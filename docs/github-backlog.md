## לקיחת משימה

1. קוראים את הכרטיס ואת התלויות, ובודקים שבעלים אחר אינו עובד באותו מסלול.
2. משייכים בעלים אחד ומציינים בכרטיס שהעבודה התחילה. חלוקת האחריות בין שני המפתחים טרם נקבעה, ולכן לא שויכו בעלים אוטומטית.
3. יוצרים ענף `codex/<issue>-<topic>` ומגבים אותו ב־commit ו־push אחרי מלוא בדיקות Docker דרך Husky.
4. PR מקושר לכרטיס, מציג תוצאה ובדיקות; בסיום מעדכנים מפת כיסוי ו־memory. סגירת כרטיס דורשת הוכחת תנאי הקבלה.

לתחילת עבודה אפשר לשקול את #12, #20, #24, #30, #31, #32; מתאמים קבצים משותפים גם כשאין תלות עסקית. הצעה לשני מסלולים: תיקוני עבר והחלפות מול תזכורות ותפעול. זו הצעת חלוקה ולא הקצאת אנשים.
